# Lessons

Rules learned from mistakes. Read before writing or reviewing anything.

| L-1 | A template file that a tool loads by name carries a `.tmpl` suffix inside this repository | A plain `CLAUDE.md` or `.gitignore` in `template/` would act on this repository | 2026-11-05 | `scripts/check.mjs` (template file list) |
| L-2 | A stub check must not pass on real work, and fails closed | An always-green gate stub hides that a project has no checks; the first stub also missed untracked files and passed outside git (T0 review) | 2026-11-05 | `scripts/check.mjs` step "template gate behaviour": docs only passes, untracked code fails, outside git fails |
| L-3 | Build a character a check looks for from its code point, never a `\u` escape in source | The file tools wrote the escapes as the literal characters twice, so the check failed on itself | 2026-11-05 | `scripts/check.mjs` passes its own em dash and Cyrillic checks |
| L-4 | Keep line endings LF in the repository and in every project | On Windows with `core.autocrlf=true`, frontmatter stops parsing and the gate script dies on `bash\r` (T0 review) | 2026-11-05 | `.gitattributes`, and `gitattributes.tmpl` in the template |
| L-5 | A step that writes a commit status, branch protection or a tag checks that it may, and hands the step to the owner when it may not | The cloud session that built T0 had push access, but its GitHub proxy refused all three writes | 2026-11-05 | T1 (kickoff), T3b (review, merge) and T4 (release) |
| L-6 | A command handed to the owner runs unchanged in bash and in PowerShell: no stdin pipes, no heredocs; `gh api` takes typed `-F` fields | The first protection handoff piped JSON into `gh api --input -`; Windows PowerShell adds a byte order mark and GitHub answered "Problems parsing JSON" (T1) | 2026-11-06 | `scripts/check.mjs` step "merge protection (fake gh)" rebuilds the handed-over body from its `-F` fields and rejects a pipe |
| L-7 | A check that judges a Markdown file reads it the way GitHub renders it, or refuses what it cannot read that way; a list of refused constructs never closes the class | Five T2 review rounds each hid an open finding from the line-based plan check in a new way (a second table, a repeated heading, a block quote, a comment, a lazy row, a fence in a list item, struck-out text, a character reference) until the files kept to a grammar of allowed lines and every cell was read as shown (T2) | 2026-11-09 | `scripts/check.mjs` step "plan and spike checks", the "hidden from the check" cases |
| L-8 | A review loop with a fresh reviewer each round has an end: after a set number of full rounds, later rounds only verify what is already found and add nothing smaller than blocking | Each fresh plan reviewer found new findings; the first headless plan stage reached round 7 with 13 findings and no end in sight (T2) | 2026-11-09 | `review.ownerDecidesAtReject` in the config, `skills/plan/SKILL.md` step 10; the T3b code-reviewer takes the same rule |
| L-9 | A guard that reads commands is tested on the commands agents really send, recorded from a real run, and its false refusals count as much as what it lets through | Every T3a review round found ordinary work refused (a commit message naming `.env`, `grep -n ".env" .gitignore`, Claude Code's `"$(cat <<'EOF' ...)"` bodies, PowerShell's `if ($?) { }` and here-strings), and one fix of a missed refusal opened another (`{owner}/{repo}`); the plan reviewer of the headless plan stage was refused in every round for a `cd` before its command (T3a) | 2026-11-09 | `scripts/check.mjs` step "hooks (recorded payloads)": the skills' and the headless runs' own commands as cases, beside the refusals |
| L-10 | A skill an agent preloads through `skills:` is named with the plugin's prefix (`pitwall:epic`) and keeps model invocation on; a Claude Code behaviour a design leans on is probed before it is built on | The implementers got no procedure at all: with `disable-model-invocation: true` Claude Code left the epic skill out of the agent without a word, which only a probe showed (T3b, 2.1.318) | 2026-11-10 | `scripts/check.mjs` step "agents" |
| L-11 | A run against real GitHub pushes `main` first and waits until Actions lists its workflow, pushes each other branch on its own, opens the PR, and waits for a check suite from GitHub Actions on its head, failing with a clear message when one does not come | One push of every branch into an empty repository, with the PR two seconds later, left GitHub with no registered workflow and the PR with no `gate` for 25 minutes, and closing and reopening the PR did not wake it (T3b, owner) | 2026-11-10 | `scripts/e2e-loop.mjs`, the start of `--github` |
| L-12 | Never roll files back with `git checkout -- <path>`, `git restore`, `git reset --hard` or `git clean` while the tree holds uncommitted work: commit it, or copy it, first | Undoing a mutation test with `git checkout` took three uncommitted fixes of the fake GitHub with it; they came back only from a copy made just before (T3b, owner) | 2026-11-10 | The PreToolUse guard refuses these commands while they would throw work away, for every agent and the main conversation (rule `uncommitted`, T4a-AC1, cases in `scripts/check.mjs`); what it cannot read before the command runs is R-3 |
| L-13 | After each change of a guard that reads commands, before the next review round, its whole corpus runs through the guard before the change and after it: the variants written for it and the command lines of the local transcripts; every verdict that changed is explained. The transcripts are the owner's own sessions: they are read where they lie, and no line of them enters the repository, whole or as a sample; `scripts/check.mjs` holds only cases written by hand | Each blocking finding of T4a's review rounds 2 to 5 was a regression of the conductor's own fix of the round before (unstaging, every git command refused in a folder the guard could not follow, a PowerShell assignment's name expanded, a variable of several paths read as one); the reviewers found them with variants and a replay of the transcripts that the conductor could have run before each round (T4a) | 2026-11-10 | `scripts/guard-corpus.mjs` (T7-AC1), which the conductor runs after each change of the guard; the next round's brief lists each changed verdict with its reason |
| L-14 | A commit runs only when the check before it passed by its own exit status: the check and the commit go in separate calls; or, in bash, they are joined by `&&` with `set -o pipefail` first whenever the check's output goes through a pipe; in Windows PowerShell 5.1, which has no `&&`, the commit goes only inside `if ($LASTEXITCODE -eq 0) { git commit ... }` right after the check | `node scripts/check.mjs 2>&1 \| grep -v "^PASS" \| tail -4 && git add <file> && git commit ...` made a commit after `GATE: FAIL`: without `pipefail` a pipeline's exit status is its last command's, and `tail` succeeds (T4b, the conductor). Implementers wrote the same form with the gate, `bash scripts/gate --fast 2>&1 \| tail -1 && git add ... && git commit ...`, in 10 calls of 6 of the 11 headless loop runs, though the epic skill says to run each command on its own; the gate happened to be green each time | 2026-11-11 | `.githooks/pre-commit`: in a project it runs `scripts/gate --fast` before every commit (T4d-AC1), and the guard's rule `precommit` refuses `git commit --no-verify` and a change of `core.hooksPath` (T4d-AC3); in pitwall it runs `scripts/check.mjs --fast` (T4d-AC4); the ways past it are R-5 |
| L-15 | A file that must run as a program (every file of the template's `scripts/` and `.githooks/`, and pitwall's own hook) is marked with `git update-index --chmod=+x` and committed by a commit that names no paths: on Windows git keeps no executable bit of its own, and a commit with pathspecs writes a new file as 100644 whatever the index says | The bit was lost three times: the gate stub (T0 review), the template's hook (T4d, which made layout.mjs --hook commit it alone) and the build stub (T4c, in the commit aae9807, put right by the commit after it); the check before each commit read the index, which still said 100755 | 2026-11-12 | `scripts/check.mjs` step "template": every file of `template/scripts/` and `template/.githooks/` and pitwall's own hook is 100755 in the index, which in CI's clone is the commit; kickoff's `git update-index --chmod=+x` names each of them and its skeleton commit names no paths; `layout.mjs` marks them on disk |
| L-16 | A change that records other changes on `main` (a release, the first commit of a loop branch) starts only when no other change of the loop is in flight, and merges only while its branch still starts at `main`'s tip; a branch left behind is named, with how to merge or delete it | A release started beside an epic still waiting for the owner's yes would conflict with that epic's records, and one merged after `main` moved would hold code nobody built, its tag refused for good (T4c review, round 1); an abandoned branch would then stop every release (owner) | 2026-11-12 | `release.mjs --plan` and `--write` refuse while an `epic/*` or `fix/*` branch, here or on origin, holds a commit `main` does not, and name each with the commands that delete it; `merge.mjs` refuses a release whose branch no longer starts at `main`'s tip; `scripts/check.mjs` step "releases (fake gh)"; for the loop's own branches, `/pitwall:continue` takes one change at a time |
