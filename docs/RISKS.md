| R-1 | The docs check of a project's plan review can still be got past by Markdown built to read one way and render another, beyond the forms it now refuses: for example a table hidden in an inline HTML span opened in the middle of a line, or a link reference definition whose label runs over two lines (T2 review, round 7), and constructs of the same kind no review reached. Only a deliberate attempt writes these (`review.findings.exotic`), so the check is not hardened against each one (ADR-0007) | The plan reviewer reads the files as written and the owner says yes to the plan before it merges; a bypass found in use becomes a BUG with a regression case in `scripts/check.mjs` | 2026-11-09 |
| R-2 | A command that hides a protected path (an encoding, a path glued together from parts, `eval`) or runs a script that writes there gets past the hooks' guards; so does a command built in the same ways to hide a push, a status write or a merge (T3a). So does a quoted heredoc of the qa agent whose first line leaves a quote open, which bash runs on into a second command (T4c review, round 3). The guards protect against mistakes, not against a deliberate bypass (`review.threatModel`); a deliberate bypass is caught by the review and the owner | Branch protection with admins included holds `main` and the required checks on GitHub (ADR-0005); `ai-review` belongs to one commit, so a change after the review needs a new one (ADR-0007); the reviewer reads the diff and the owner merges high risk; a bypass found in use becomes a BUG with a regression case in `scripts/check.mjs` | 2026-11-09 |
| R-3 | The L-12 guard judges a command line before it runs, on the tree as it is then, and some lines do what it cannot see: a stash or a commit joined by `;` that fails still counts as kept; `cd -` and `popd` are not followed; `git checkout` without `--` over paths only the run knows (`git checkout "$f"` in a loop over changed files, `git checkout HEAD $P`, `git checkout $(git diff --name-only)`) reads them as a branch, or as a path that matches nothing, and passes; in a folder named through a variable the line does not set or a command's output other than `$(git rev-parse --show-toplevel)` (a backtick substitution or PowerShell's `$x = (git rev-parse --show-toplevel)` included), a command that can throw work away is refused as unreadable, and a `git checkout <name>` there that could be a branch is taken for one; a variable the line set before and sets again through `while read`, `foreach`, `+=`, `declare`, `local`, an array or after a keyword (`do D=$d`) keeps its earlier value; a bash variable holding one path with a space is not followed, so a rollback of it is judged on the whole tree and a folder named by it reads as unreadable; `git clean -e` counts the files it excludes; a stash popped with a conflict cannot be dropped; a rename staged and then deleted is refused by `git reset --hard` (T4a reviews, rounds 1 to 5 and the verifying round); a stash or a commit of a work tree earlier in the same line does not count for `git worktree remove --force` after it, which asks for a call of its own (T7). Three commands it did not judge at all were bugs, not risks, and T7 fixed them: BUG-1 (`git rm -f`), BUG-2 (`git worktree remove --force`) and BUG-3 (`git reset --merge`). An honest agent rarely writes these, so the guard is not made to run the line in its head | L-12 tells every agent to commit or copy work before a rollback, and the reviewer reads what a change throws away; a case found in use becomes a BUG with a regression case in `scripts/check.mjs` | 2026-11-10 |

The headless runs allow merge.mjs with any arguments and check instead that the scripted owner was asked before the merge. | A case of 1 to 4 that happens is filed with /pitwall:bug. For 5, the owner keeps Claude Code's default mode while the loop runs, or reads the command a permission prompt shows before allowing it. | 2026-11-11 |
| R-5 | The gate before every commit (T4d, ADR-0012) is a git hook, and the guard's rule against skipping it is narrow by the owner's decision, so a commit can still land without the gate (owner, 2026-11-12): through `git -c core.hooksPath=<another folder> commit`; through an abbreviation of `--no-verify` that git accepts, such as `--no-veri`; after a change or deletion of `.githooks/pre-commit` or `scripts/gate`, which the guard does not touch; after `core.hooksPath` is changed some way other than `git config` (an edit of `.git/config`, `git config --edit`, `--remove-section core`); and in a new clone until `/pitwall:continue` sets `core.hooksPath` | CI runs the gate on every PR as the required check `gate` (ADR-0002, ADR-0005); the code reviewer counts a change to `.githooks/` or `scripts/gate` in a change that is not about them as a blocking finding; L-14 tells every agent to commit only after a green check; a skip found in use becomes a BUG with a regression case in `scripts/check.mjs` | 2026-11-12 |
| R-6 | Nothing but the release skill's text keeps the main conversation, or an agent, from running the commands `release.mjs --tag` hands the owner: `git tag -a`, `git push origin v<x.y.z>` and `gh release create` (T4c review, round 1); the same kind of exposure as R-4 item 5.
